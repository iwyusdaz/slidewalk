Accessibility statement

Honest framing: nothing here claims WCAG conformance or certification. What follows is exactly what was tested, with which tools, on which date — and what was not tested.

Scope

This statement covers: this case-study site (docs/index.html and this page) and the reference deck it links to (docs/deck.html). The gate runner and builders in the repository are code, not user-facing pages, and are out of scope.

What was NOT tested

  • No screen reader testing. Nobody has operated this deck with VoiceOver, NVDA or JAWS. Automated checks cannot tell you what a screen reader user actually experiences.
  • No testing with people. No disabled users, no educators, no learners have reviewed the deck or the site.
  • Alt text quality. The gates verify alt text exists; only a human can judge whether it is good.
  • The PPTX. The PowerPoint file shares the deck's text and notes but has not been checked with PowerPoint's built-in Accessibility Checker. If you distribute the PPTX, run that check once in PowerPoint.

Known issues and limitations

  • Speaker notes are hidden until toggled (button or N). Screen reader users can reach them via the toggle; they are always included in print and in the PPTX notes pane.
  • The deck relies on JavaScript for slide navigation. Without JavaScript, all slides render as a scrollable document (the hidden attribute is applied by script, so no-JS readers still get full content). This has not been verified with a no-JS screen reader pass.
  • Auto-generated checkpoint questions have not been reviewed by an educator.
